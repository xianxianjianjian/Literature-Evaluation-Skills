# Literature Evaluation Plugin V1.2.0

Status: **historical development candidate only; never released or tagged. Superseded by v1.3.0.**

This file preserves the scope of the unreleased v1.2 development milestone. The formal release lineage skips directly from `v1.1.0` to `v1.3.0`; no standalone `v1.2.0` tag exists or is planned. See `docs/releases/v1.2-development.md` for the maintained milestone record.

## Translation mirror hardening

- Adds explicit workflow translation scope.
- Requires `source_inventory.json`, `translation_ledger.jsonl`, issue records and an independently generated validation report for every manifest translation scope; `FULL_MIRROR` additionally requires `mirror_layout_plan.json`.
- Adds independent `validate_translation_package.py` reporting.
- Rejects missing Main/SI figures or tables, unmapped source pages, malformed ledger records, flattened table topology and incomplete render QC.
- Keeps source-version identity in `source_manifest.json` without per-object hashes.

The evidence-package design is informed by the structured document/object provenance used by Docling, GROBID and PaperQA, without adding those projects as runtime dependencies.

## Psychology and cognitive-neuroscience reading

- Organizes deep reading into positioning, reconstruction and audit passes.
- Routes APA JARS, JARS-Qual/MMARS, STROBE, CONSORT-SPI and COBIDAS prompts according to the actual design.
- Adds dedicated cross-sectional mediation/SEM temporality warnings.
- Requires estimate/interval/effect-size/scientific-meaning interpretation rather than p-threshold conclusions.
- Keeps reporting completeness separate from validity judgment and adds no quality score.

Primary maintained sources are listed in `skills/paper-deep-reading/references/psychology-methods-routing.md`.

## DOCX hygiene

- Adds deterministic B metadata/comment removal.
- Validates `docProps/core.xml`, extended/custom properties and comment parts.
- Defaults to no author; an explicitly supplied author is preserved exactly.

## Compatibility

- The weekly state schema remains version 1 and keeps the existing state vocabulary.
- Older manifests remain readable; a missing translation scope must be supplied before Translation can become `COMPLETE`.
- Search and Zotero behavior are unchanged except for carrying translation scope through orchestration.
